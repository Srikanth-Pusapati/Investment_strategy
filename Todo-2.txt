THE MODEL (vision)
  Scanner -> Decision -> Execute -> Monitor.  Fully DISCOVERY-DRIVEN; NO watchlist.
  - Scanner surfaces interesting/new names from signals.
  - Decision (Claude + deterministic risk) judges worth-buying + size.
  - Execute places the trade for the sized amount.
  - Monitor (watchdog) holds/sells to realize profit or cap loss.
  Paper account: $100k.  Live account: $100–$1000 only (scale up from a track
  record, never risk it all).
  NORTH STAR: multi-user — several people run the model on THEIR OWN accounts.

HONEST CONSTRAINTS (read before "keep it from going below principal")
  - No strategy can GUARANTEE you never drop below principal — gaps/halts/fast
    crashes jump through stops. Goal = SMALL, BOUNDED, SURVIVABLE losses.
  - IPOs: NOT available via Alpaca's API (no new-issue allocation). Out of scope;
    we can still trade post-IPO names the scanner finds.
  - Options need ~$2–3k to be usable (1 contract ≈ $100–500 premium; the 1%
    premium cap on $1k = $10, buys nothing). Small accounts = equity/ETF/fractional.
  - ACCOUNT TYPE (decided 2026-06-29): Alpaca is MARGIN-ONLY (no cash account), so
    the small live float is a margin account. Consequences handled in code:
      * PDT guard (1.1) is now ESSENTIAL — it pauses new buys at the day-trade line.
      * NO-LEVERAGE gross cap (1.7) pins total deployment to <=100% of equity so we
        never trade on the ~2x margin buying power (no borrowed money).
    Margin is available but we deliberately don't use it.
  - Tiny accounts: spread/slippage dominate; the edge must clear costs.

CAPITAL-PRESERVATION STACK (what keeps the account afloat)
  IN PLACE: %-based position/exposure/daily-loss/peak-drawdown caps; vol-targeted
    fractional-Kelly sizing; exchange brackets (stop+take); watchdog (emergency
    flatten, trailing stops, hard stops for fractional, latched equity floor);
    fractional shares; defined-risk-only options (premium-capped, no naked/short);
    kill switch; paper/live interlock; earnings-blackout guard; account P&L tracker.
  TO ADD: see Phase 1.

Reference infra in place:
- Shared per-cycle Quiver client (Bearer auth, 429 backoff, cache).
- safe_fetch/safe_scan degrade a flaky/wrong endpoint to [] (no crash).
- Adding a signal/screener is trivial (subclass + register; verify schema first).
- Deterministic, well-tested risk core the LLM cannot override (the safety core).
- Account P&L truth = Alpaca account (status.py), NOT the ledger.

PHASE 1B — Capital-preservation HARDENING  (audit 2026-06-30; DO BEFORE LIVE $)
################################################################################
From the 2026-06-30 code audit. Phase 1's caps are sound, but the LIVE posture
exposes gaps that the $100k paper book hides. Two LIVE facts make these permanent
constraints, not things we can design away:
  - LIVE balance is SMALL ($100–$1000) => MOST positions are FRACTIONAL. Fractional
    MUST keep working; we harden around it, we don't avoid it.
  - Account is MARGIN-ONLY (Alpaca has no cash account) => buying_power is ~2x, so
    the broker will NOT reject an over-deploy for us; our caps are the only guard.
RED = pre-live blocker.  YELLOW = roadmap / tune after backtest.

[DONE 2026-06-30] 1B.1 (RED) Alerting on watchdog CRITICAL (was 4.1, promoted).
        notify.py Alerter pages a human on every watchdog CRITICAL (failed
        flatten/stop/trailing close = a NAKED position) and on the latched equity-
        floor halt. Self-contained (the bot is a long-lived process; it can't call
        Claude's Gmail MCP): sinks are Gmail SMTP (stdlib smtplib, app password) and
        an optional generic webhook (Slack/Discord/PagerDuty). FAILS OPEN (never
        raises into the safety loop; the event is logged at CRITICAL regardless) and
        THROTTLED per event key (ALERT_COOLDOWN_SECONDS, default 15m) so the 30s
        retry loop can't spam. A key is only marked sent when a sink actually
        delivers, so a transient send failure retries next tick. Log-only until
        ALERTS_ENABLED + a sink. Config: ALERTS_ENABLED, ALERT_SMTP_*, ALERT_EMAIL_TO,
        ALERT_WEBHOOK_URL, ALERT_COOLDOWN_SECONDS. Tests: test_notify.py (11).
[DONE 2026-06-30] 1B.2 (RED) Fractional-position protection (the live default).
        (a) self.exits already persists+reloads (state.py exits dict; tested in
        test_state). (b) submit_from_decision now REFUSES any buy whose decision
        carries no stop (stop_loss_pct<=0) — a whole-share bracket needs a stop
        leg and a fractional buy needs a watchdog stop, so we never open a naked
        position; orchestrator registers the watchdog stop on every fractional
        fill. (c) already PREFERS the whole-share exchange bracket whenever >=1
        share is affordable (drops the sub-share remainder). (d) documented the
        irreducible fractional overnight/halt-GAP residual (bounded, not
        removable; see 1B.5). Tests: test_execution.py (6).
[DONE 2026-06-30] 1B.3 (RED) Intra-cycle stale-snapshot over-deploy. The account is
        still fetched once per cycle, but each fill now folds back into that
        in-memory snapshot: _apply_pending_buy adds/extends the position and draws
        down cash+buying_power; _apply_pending_close returns a decision-sell's value
        and frees its slot. So later proposals in the SAME cycle see prior buys as
        deployed — the no-leverage gross cap, cash buffer, and max-open-positions
        can no longer be jointly breached in one multi-buy cycle (the margin ~2x
        buying_power won't reject it, so our caps are the only guard). Conservative
        (uses full approved_notional even though whole-share drops the sub-share
        remainder). Tests: test_orchestrator.py (5).
[DONE 2026-06-30] 1B.4 (RED) Held-position KEEP-vs-SELL review (note 3). Added a
        DETERMINISTIC, LLM-independent time-stop that recycles dead/flat capital:
        PortfolioState now persists a per-symbol hold clock (entry_times; set on the
        opening buy, with a watchdog first-seen fallback so a restart / pre-existing
        position still gets a clock). The watchdog's _enforce_time_stop closes a
        position held past MAX_HOLD_DAYS (default 30) that never reached
        TIME_STOP_MIN_GAIN_PCT (default 2%) — a winner is left to the trailing
        stop/take, only stalled money is rotated out. Config: MAX_HOLD_DAYS (0=off),
        TIME_STOP_MIN_GAIN_PCT. Tests: test_watchdog.py (+4), test_state.py (+2).
        STILL OPEN (1B.4b): a full signal-freshness / thesis-decay exit that runs
        independently of the LLM (deterministically SELL a held name whose entry
        signals have gone stale/uncorroborated, not just gone flat). The time-stop
        covers the "held forever" gap; thesis-decay is best tuned against the 2.1
        backtest and folded into the decision engine's held-name review.
[ ] 1B.5 (YELLOW) Market-closed / halt exit fallback. Every exit is a MARKET order,
        which can't fill when the market is closed or a name is LULD-halted — i.e. a
        gap-down / limit-down is exactly when the flatten fails. Rest GTC protective
        stops for whole-share; add a marketable-limit fallback; accept + document
        that fractional overnight-gap risk is bounded, not removable.
[ ] 1B.6 (YELLOW) Regime flip must de-risk the EXISTING book, not just new buys.
        Today the regime multiplier only shrinks NEW positions; held names ride a
        downturn to their own stops with no account-level trim. Add a regime-off
        TRIM so "salvage when the market is down" has an active lever.
[ ] 1B.7 (YELLOW) yfinance correlated fail-open. Regime filter AND sector cap both
        source yfinance and BOTH fail open (full size, no cap), so one yfinance
        outage drops two risk-off guards at once — during the vol spike they exist
        for. Log LOUDLY on degrade and size DOWN (not full) when both are missing;
        long-term move to the paid feed (2.2).
[ ] 1B.8 (YELLOW) Let winners run. The hard take-profit closes the FULL position at
        ~+12% and pre-empts the trailing stop, so winners are capped while losers
        run to the stop — capping the asymmetric edge that pays for the losers. Add
        scale-out (sell a piece at target, trail the rest; submit_ladder already
        exists) and/or a vol-scaled take. Tune against the 2.1 backtest.
[ ] 1B.9 (YELLOW) Persist _pending_oids + add a min-conviction gate. Reconciliation
        state is in-memory (a reject/partial across a restart is never reconciled,
        leaving a phantom ledger intent); a 0.1-conviction buy that merely clears
        the friction floor still fires. Persist the pending list; add a conviction
        floor so only real edges trade.
