  call. Far cheaper in tokens (Todo item 2 warns about exactly this).
- They DEBATE risk with LLM personas; we use a DETERMINISTIC risk core the LLM
  cannot override. For real money this is a safety SUPERIORITY, not a gap — keep.

  [DONE] Technical analyst -> signals/technical.py (RSI/MACD/trend, yfinance, no

         unit-tested in tests/test_technical.py (indicator math).
  [DONE] Bull/Bear debate value imported CHEAPLY: prompt now has Claude reason

  [DONE] Reflection/memory loop (their best idea; == Todo 3.1 signal attribution):
         attribution.py reconstructs closed round-trips from the ledger, scores

2. Quiver — getting the most out of your paid tier
What you use today: only congressional trading — per-symbol historical (signals/congress.py) + the cross-ticker live feed (screener/congress_feed.py). That's ~10% of what you're paying for.

The architecture makes adding datasets trivial — subclass SignalProvider (scores a known symbol) or Screener (discovers new symbols), and the safe_fetch/safe_scan wrapper guarantees a flaky endpoint returns [] instead of crashing the loop. Register in the relevant aggregator.

Highest-value Quiver datasets to add, ranked by signal/timeliness:

Dataset	Endpoint	Layer	Why	Lag
Off-exchange / dark-pool short vol	live/offexchange	signal + screener	Most timely Quiver data (daily); institutional short pressure	~1 day
WallStreetBets mentions	live/wallstreetbets	screener	Retail momentum/squeeze early-warning	~1 day
Gov contracts	live/govcontracts	signal	Hard future-revenue catalyst per ticker	days
Senate/House split	live/senatetrading,housetrading	signal	Some members outperform; finer than aggregate congress	~45d
Lobbying spend	live/lobbying	signal (weak)	Slow regulatory-tailwind tell	weeks
13F institutional changes	historical/sec13f...	signal (slow)	"Smart money" positioning	quarterly
Caps / how to proceed (this is the important part):

Rate limits are the real constraint. Quiver paid tiers are typically ~300 req/min. Your current code already has an inefficiency: congress is pulled twice (per-symbol historical fan-out in the signal layer and the live cross-ticker feed in the screener). The live feed already contains the per-symbol data. Fix: one shared, cached Quiver client — pull the live/bulk feed once per cycle, serve both layers from it. This is the single most important change before adding 5 more datasets, or you'll hit 429s.
Prompt-token cost scales with signals. Every dataset you add lands in the decision prompt → more Opus output tokens (your dominant cost via DECISION_EFFORT). Keep each provider's summary terse and rely on the numeric score; don't dump raw payloads.
Weight by lag in the score, not just presence. Congress (~45d lag) should never move size like off-exchange (~1d). The code already does cluster-saturation weighting for congress — apply the same discipline per dataset.
MAX_DISCOVERED_CANDIDATES=12 is your backpressure valve on the screener fan-out. As you add screeners, corroboration (a name flagged by congress + dark-pool + WSB) auto-ranks to the top via score summing in screener/aggregator.py:60 — good. Keep the cap modest.
Concrete first step I'd recommend: build signals/quiver_client.py — a shared client with Bearer auth, tenacity retry + 429 backoff (already a dep), and a per-cycle response cache keyed by (dataset, symbol). Then refactor the two existing congress callers onto it, then add offexchange and wallstreetbets. That's the cleanest path that also fixes the double-pull.
