Reference infra that's already in place:
- Shared per-cycle Quiver client: signals/quiver_client.py (Bearer auth, 429
  backoff, per-cycle cache). new_cycle() at top of each decision cycle.
- safe_fetch / safe_scan make a flaky/wrong endpoint degrade to [] (no crash).
- Adding a dataset is now trivial:
  * screener: subclass Screener; in scan() call self.quiver.live("<dataset>");
    add to screener/aggregator._REGISTRY and (if Quiver-backed) _QUIVER_SCREENERS.
  * signal: subclass SignalProvider(cfg, quiver); in fetch() read
    self.quiver.live("<dataset>") and filter by symbol; add to SignalAggregator.
  * VERIFY THE RESPONSE SCHEMA against Quiver docs / scripts/inspect_quiver.py
    before scoring (field names differ per dataset).
Cross-cutting cautions when adding datasets:
- Token cost scales with signals (every dataset lands in the Opus prompt). Keep
  each provider's summary terse; rely on the numeric score, don't dump payloads.
- Weight by lag in the score, not just presence. Congress (~45d) must not move
  size like off-exchange (~1d). Apply the cluster-saturation discipline per set.
- MAX_DISCOVERED_CANDIDATES=12 is the screener backpressure valve; keep it modest.
  Corroboration (a name flagged by multiple sources) auto-ranks via score summing
  in screener/aggregator.py.
