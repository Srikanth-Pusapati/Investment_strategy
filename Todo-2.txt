THE MODEL (vision)
  Scanner -> Decision -> Execute -> Monitor.  Fully DISCOVERY-DRIVEN; NO watchlist.
  - Scanner surfaces interesting/new names from signals.
  - Decision (Claude + deterministic risk) judges worth-buying + size.
  - Execute places the trade for the sized amount.
  - Monitor (watchdog) holds/sells to realize profit or cap loss.
  Paper account: $100k.  Live account: $100–$1000 only (scale up from a track
  record, never risk it all).
  NORTH STAR: multi-user — several people run the model on THEIR OWN accounts.

HONEST CONSTRAINTS (read before "keep it from going below principal")
  - No strategy can GUARANTEE you never drop below principal — gaps/halts/fast
    crashes jump through stops. Goal = SMALL, BOUNDED, SURVIVABLE losses.
  - IPOs: NOT available via Alpaca's API (no new-issue allocation). Out of scope;
    we can still trade post-IPO names the scanner finds.
  - Options need ~$2–3k to be usable (1 contract ≈ $100–500 premium; the 1%
    premium cap on $1k = $10, buys nothing). Small accounts = equity/ETF/fractional.
  - MARGIN amplifies losses + triggers PDT — DON'T use it on the small account.
    Run the small live float as a CASH account (no leverage, no PDT rule).
  - Tiny accounts: spread/slippage dominate; the edge must clear costs.

CAPITAL-PRESERVATION STACK (what keeps the account afloat)
  IN PLACE: %-based position/exposure/daily-loss/peak-drawdown caps; vol-targeted
    fractional-Kelly sizing; exchange brackets (stop+take); watchdog (emergency
    flatten, trailing stops, hard stops for fractional, latched equity floor);
    fractional shares; defined-risk-only options (premium-capped, no naked/short);
    kill switch; paper/live interlock; earnings-blackout guard; account P&L tracker.
  TO ADD: see Phase 1.

Reference infra in place:
- Shared per-cycle Quiver client (Bearer auth, 429 backoff, cache).
- safe_fetch/safe_scan degrade a flaky/wrong endpoint to [] (no crash).
- Adding a signal/screener is trivial (subclass + register; verify schema first).
- Deterministic, well-tested risk core the LLM cannot override (the safety core).
- Account P&L truth = Alpaca account (status.py), NOT the ledger.
